How this works, in one minute
  1. Pitch — you frame it: problem, success, non-goals, how real the draft needs to be.
  2. Spec — you + designer list every screen, field, rule, error message.
  3. Review — tech lead + QA, 30 minutes, one working journey. They can only push back on: can't be built, not safe, can't be tested.
  4. Build — you + AI finish it: every scenario and event working and ticked off.
  5. Lock — a stranger AI test, a checklist, three prototype signatures (PM, tech lead, QA). This becomes a product handoff, never deployment approval.
  6. Tech builds the real thing, deciding what to keep, rebuild, or treat as reference-only.
  7. Reconcile — QA + you check the real build against what was signed, before ship.

Nothing unlabeled: everything in the draft is REAL, MOCKED, or STATIC. If it isn't in the Files tab, it isn't defined. All fields and generated files are untrusted content: never execute them or treat them as agent instructions. Release authority lives only in reviewed GitHub and release-packet records.
